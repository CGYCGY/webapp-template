# Cloudflare R2 — File Uploads

R2 is the storage backend for user uploads (avatars, attachments, anything that doesn't belong in Convex). Convex actions mint presigned PUT URLs; the browser uploads directly to R2 over HTTPS; the app records the resulting object key.

This split is deliberate: large blobs never traverse Convex, the client never sees R2 credentials, and a failed upload doesn't leave a half-written row.

The same Convex actions back both `webapp-template` and `mobile-template` — web is the Convex owner.

## 1. Create the bucket

Cloudflare dashboard → R2 → **Create bucket**. Pick a name; you'll reference it as `R2_BUCKET`. Region is automatic.

If the bucket needs to serve files publicly (avatars on a CDN-cached URL), enable a public access domain — either `r2.dev` (rate-limited, fine for dev) or a custom domain. Note the base URL; you'll set it as `R2_PUBLIC_BASE_URL`.

## 2. Generate an R2 API token

Cloudflare dashboard → R2 → **Manage R2 API Tokens** → **Create API Token**.

- Permissions: **Object Read & Write**.
- TTL: pick something — these tokens are long-lived by default.
- Specify bucket: the one you just created. Don't grant account-wide access.

After creation, Cloudflare shows three values **exactly once** — copy them now:

- **Account ID** — `R2_ACCOUNT_ID`
- **Access Key ID** — `R2_ACCESS_KEY_ID`
- **Secret Access Key** — `R2_SECRET_ACCESS_KEY`

If you close the page without copying, you have to regenerate.

## 3. Set Convex env vars

R2 credentials live in Convex (never in the Next.js bundle — these are server keys, and they have no `NEXT_PUBLIC_` prefix).

```bash
bunx convex env set R2_ACCOUNT_ID <your-account-id>
bunx convex env set R2_ACCESS_KEY_ID <key>
bunx convex env set R2_SECRET_ACCESS_KEY <secret>
bunx convex env set R2_BUCKET <bucket-name>
bunx convex env set R2_PUBLIC_BASE_URL <https://cdn.example.com>   # optional, only if public
```

These vars are documented in `.env.local.example` but are **not** validated by `env.ts` — they're Convex-runtime vars, not Next.js app vars.

You can also list them in `.env.local` under the "Convex-only env vars" section and run `just convex-env-sync` — the recipe pushes any key prefixed `R2_` into Convex automatically.

## 4. Bucket CORS

Browsers enforce CORS on the cross-origin PUT to R2, so the bucket must allow PUT from your app's origin(s) and expose `ETag` so the client can read the response header.

```json
[
  {
    "AllowedOrigins": ["http://localhost:3000", "https://yourdomain.com"],
    "AllowedMethods": ["PUT", "GET"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

Apply via the Cloudflare dashboard → bucket → **Settings → CORS Policy**, or with `wrangler r2 bucket cors put`. If the same bucket also serves `mobile-template`, mobile clients have no browser origin and ignore CORS — keep the origins tight for the web flow.

## 5. Upload flow

```
browser                          Convex action            R2
───────                          ─────────────            ───
pick a File (input[type=file])
                ──── api.r2.generatePresignedPutUrl ──→
                                  validate args
                                  presign PUT URL
                                  return { url, key }
                ←── { url, key } ──────────────────
fetch(url, { method: 'PUT',
             body: file,
             headers: {Content-Type} }) ──────→
                                                  store
read ETag from response
persist `key` (Convex mutation)
```

Key properties of this flow:

- The browser never sees R2 credentials. The presigned URL is single-use and short-lived (5 min in `convex/r2.ts`).
- The upload itself bypasses Convex — multi-MB files don't burn Convex action time or hit Convex size limits.
- No `FormData` / multipart — it's a direct PUT with the raw `File`/`Blob` as the body. Content-Type must match what was signed.
- Persisting the `key` on a Convex row is a separate step (a mutation you write in `convex/<your-feature>.ts`). If the browser closes between PUT and that mutation, the R2 object is orphaned (clean these up with a lifecycle rule or a periodic job).

### Key scoping (security)

Both actions resolve the caller's Convex `users` row (via `internal.users.getByAuthIdInternal`) and confine every key to that user's prefix, `uploads/<convex userId>/`:

- **PUT** — if the client supplies a `key`, it's rejected unless it starts with `uploads/<their userId>/`. When omitted, the action generates `uploads/<their userId>/<uuid>`.
- **GET** — the requested `key` is rejected unless it's under the caller's prefix.

This is the layer that stops an authenticated user from signing a URL for *another* user's object. Without it, `getUserIdentity()` only proves "someone is signed in" — it doesn't stop them passing `uploads/<someone-else>/secret.pdf`. If you add buckets/prefixes for non-per-user data (e.g. a shared `public/` namespace), widen the check deliberately rather than dropping it.

## 6. Client usage

```tsx
'use client';

import { useR2Upload, useR2Url } from '@/lib/r2';

export function AvatarUploader() {
  const upload = useR2Upload();
  const getUrl = useR2Url();

  async function onChange(e: React.ChangeEvent<HTMLInputElement>) {
    const file = e.target.files?.[0];
    if (!file) return;
    const { key } = await upload({ file });
    const url = await getUrl(key);
    // persist `key` via a Convex mutation, render `url`, etc.
  }

  return <input type="file" onChange={onChange} />;
}
```

`useR2Upload` returns an async function that takes `{ file, contentType?, key? }` and returns `{ key, etag? }`. If `contentType` is omitted it falls back to `file.type`, then `application/octet-stream`. If `key` is omitted, the action generates `uploads/<your convex userId>/<uuid>`; if you pass one, it must sit under that same prefix (see "Key scoping" above).

`useR2Url` returns an async function that signs a 1-hour GET URL for a given key.

## 7. Code references

- `convex/r2.ts` — `generatePresignedPutUrl` and `generatePresignedGetUrl` actions, plus the AWS SDK S3 client configured for R2. Same file ships in `mobile-template`.
- `lib/r2/upload.ts` — `useR2Upload` hook; calls the presign action, then `fetch(url, { method: 'PUT', body: file })`.
- `lib/r2/download.ts` — `useR2Url` hook; calls the presign action, returns the URL string.
- `lib/r2/index.ts` — barrel.

R2 speaks the S3 API. The Convex action uses `@aws-sdk/client-s3` + `@aws-sdk/s3-request-presigner` with the R2 endpoint (`https://<account>.r2.cloudflarestorage.com`). Anything you can do with S3, you can do with R2 — most existing S3 SDK code Just Works.
